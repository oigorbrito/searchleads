## 2025-02-17 - Pre-compute Blocking Keys in Entity Resolution Pairwise Evaluation
**Learning:** In entity resolution blocking metrics calculation (`evaluate_blocking_corpus`), calculating record blocking keys inside the $O(N^2)$ pairwise combination loop (`combinations(records, 2)`) invoked `blocking_keys` $N(N-1)$ times instead of $N$ times. Each `blocking_keys` call triggers multiple regexes, candidate fact instantiations, and Unicode normalizations (`unicodedata.normalize`), causing severe performance degradation (~288 ms for 108 records).
**Action:** Always pre-compute derived feature vectors or blocking keys per record into a list of `(record, keys)` tuples prior to generating pairwise combinations. This reduces key extractions from $O(N^2)$ to $O(N)$ and yields a ~68x speedup.
