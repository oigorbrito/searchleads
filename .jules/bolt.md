## 2025-02-18 - String folding optimization with LRU Cache and ASCII Fast Path
**Learning:** In string folding and diacritic-stripping functions (`NFKC` / `NFKD` decomposition + combining mark removal), diacritic decomposition loops over every character incur high CPU overhead. ASCII strings (`text.isascii()`) never contain combining diacritics, so NFKD filtering can be bypassed completely. In ER and entity deduplication workloads where candidate names, locations, and roles repeat across pairwise comparisons, decorating `_fold` with `@functools.lru_cache(maxsize=2048)` reduces repeated folding execution time from ~0.46s to ~0.017s for 120,000 strings (~26x speedup).
**Action:** Always check `text.isascii()` before character-by-character diacritic stripping and use `@functools.lru_cache` on pure text normalization functions called repeatedly during blocking and ER feature comparison.
